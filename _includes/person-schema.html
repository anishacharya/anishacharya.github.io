{%- comment -%} schema.org Person, emitted on every page. Why this exists: searching "anish acharya phd" returns a Knowledge Graph card whose text describes this Anish Acharya but whose photo is Anish Acharya the a16z general partner. Two people share the name string, one has far more press coverage, and with no structured data here there was nothing telling a crawler that this site, this Scholar profile, this GitHub account and this LinkedIn account are one entity distinct from that one. `sameAs` is the property Google's entity reconciliation actually reads — a set of authoritative profile URLs it can cross-check. `disambiguatingDescription` exists in the vocabulary for exactly this case: two entities with the same name. Neither guarantees the card gets fixed (Google decides), but without them there is no signal to act on at all. Emitted site-wide rather than only on the homepage so any entry point carries the identity. ORCID and Scopus are wired in below (both in `sameAs` and as `identifier` PropertyValues). alphaXiv, Semantic Scholar (author 40026200, verified against the paper list) and the UT Austin Center for Big Data Analytics member page are in `sameAs`.
